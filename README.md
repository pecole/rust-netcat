# rust-netcat

Rust で実装した netcat クローンです。TCP / UDP のクライアント・サーバーとして動作し、
ポートスキャンの簡易確認、ファイル転送、簡易チャット、リモートコマンド実行 (`-e`) など、
本家 `nc` の基本的な使い方をひととおりカバーしています。

> **注意:** `-e`/`--exec` オプションは接続相手にシェルを渡す機能です。CTF や自分の検証環境、
> 許可を得たペネトレーションテストなど、正当な用途でのみ使用してください。

## 特徴

- TCP / UDP のクライアント・サーバーモード
- `-l` によるリッスン(サーバー)モード、`-k` で複数接続を順次受け付け続ける
- `-e` でコマンドを実行し、その標準入出力を接続先に接続(リバースシェル/バインドシェル用途)
- `-w` で接続タイムアウト・読み取りタイムアウトを指定
- `-v` で詳細ログを表示
- IPv6 アドレスにも対応

## インストール

### 前提

- [Rust ツールチェイン](https://www.rust-lang.org/tools/install)(`cargo`)がインストールされていること

### ソースからビルド

```bash
git clone https://github.com/pecole/rust-netcat.git
cd rust-netcat
cargo build --release
```

ビルドが成功すると `target/release/rnc` に実行ファイルが生成されます。

### インストール(パスを通す)

```bash
cargo install --path .
```

`~/.cargo/bin/rnc` にインストールされ、`PATH` に `~/.cargo/bin` が通っていればどこからでも
`rnc` コマンドとして実行できます。

## 使い方

コマンド名は `rnc` です。

```
使用法: rnc [OPTIONS] [HOST] [PORT]

引数:
  [HOST]  接続先ホスト(クライアントモード)/ バインドアドレス(サーバーモード、デフォルト 0.0.0.0)
  [PORT]  接続先ポート(クライアントモード)/ リッスンポート(サーバーモード)

オプション:
  -l, --listen             接続を待ち受けるサーバーモードにする
  -u, --udp                TCP の代わりに UDP を使う
  -v, --verbose...         詳細な出力(-v, -vv でさらに詳細)
  -k, --keep-open          サーバーモードで、接続が終了しても待ち受けを継続する
  -p, --port <PORT>        リッスンポートの指定(位置引数の代わり)
  -w, --timeout <TIMEOUT>  接続タイムアウト・読み取りタイムアウト(秒)
  -e, --exec <EXEC>        接続確立後にコマンドを実行し、標準入出力を接続に流す(TCP のみ)
  -h, --help               ヘルプを表示
  -V, --version            バージョンを表示
```

### 1. TCP でメッセージを送受信する

サーバー(待ち受け側):

```bash
rnc -l -p 4444
```

クライアント(接続側、別端末で実行):

```bash
rnc 127.0.0.1 4444
```

どちらの端末でも入力した文字列がそのまま相手の画面に表示されます(標準入力 ⇔ 標準出力)。

### 2. ファイルを転送する

受信側:

```bash
rnc -l -p 4444 > received_file.txt
```

送信側:

```bash
rnc -w 2 127.0.0.1 4444 < send_file.txt
```

### 3. 複数の接続を順に受け付ける(`-k`)

```bash
rnc -l -k -p 4444
```

1 つの接続が終了しても、プロセスは終了せず次の接続を待ち受け続けます。

### 4. UDP モード

サーバー:

```bash
rnc -u -l -p 5353
```

クライアント:

```bash
rnc -u 127.0.0.1 5353
```

### 5. ポート接続確認(簡易ポートスキャン)

```bash
rnc -v -w 1 example.com 80
```

`-v` で接続結果を標準エラー出力に表示し、`-w` でタイムアウトを指定することで、
ポートが開いているかどうかを素早く確認できます。

### 6. コマンド実行と接続を結びつける(`-e`)

サーバー側で `bash` を待ち受けさせる例(いわゆるバインドシェル):

```bash
rnc -l -p 4444 -e "/bin/bash"
```

クライアント側から接続すると、リモートの `bash` に標準入出力が接続されます。

```bash
rnc 127.0.0.1 4444
```

> **セキュリティ上の注意:** このオプションは接続してきた相手に任意コマンド実行の権限を
> 与えます。インターネットに公開したホストや、許可のないネットワーク上で使用しないで
> ください。CTF・学習用のラボ環境や、許可された侵入テストなどでのみ使用してください。
