# rust-netcat

Rust で実装した netcat クローンです。TCP / UDP のクライアント・サーバーとして動作し、
ポートスキャンの簡易確認、ファイル転送、簡易チャット、リモートコマンド実行 (`-e`) など、
本家 `nc` の基本的な使い方をひととおりカバーしています。

さらに、本家 `nc` にはない機能もいくつか追加しています: 通信のhexダンプ/統計表示、
JSON構造化ログ、受信内容の正規表現フィルタ、帯域制限、接続リトライ、複数クライアント
間のブロードキャスト(簡易チャットルーム)、SOCKS5プロキシ経由の接続、TLS対応。

> **注意:** `-e`/`--exec` オプションは接続相手にシェルを渡す機能です。CTF や自分の検証環境、
> 許可を得たペネトレーションテストなど、正当な用途でのみ使用してください。

## 特徴

- TCP / UDP のクライアント・サーバーモード
- `-l` によるリッスン(サーバー)モード、`-k` で複数接続を順次受け付け続ける
- `-e` でコマンドを実行し、その標準入出力を接続先に接続(リバースシェル/バインドシェル用途)
- `-w` で接続タイムアウト・読み取りタイムアウトを指定
- `-v` で詳細ログを表示
- IPv6 アドレスにも対応
- **`-x`/`--hex`**: 通信内容をxxd形式でstderrにダンプ
- **`--stats`**: 転送バイト数・経過時間・スループットを表示
- **`--timestamp`**: hexダンプに経過時間のマーカーを付与
- **`--json-log`**: 接続/切断/データ/エラーイベントをJSON Linesでファイルに記録
- **`--filter`**: 受信データを正規表現でフィルタして表示(マッチした行だけ表示)
- **`--rate-limit`**: 転送速度を指定バイト/秒に制限
- **`--retry`/`--retry-delay`**: クライアント接続失敗時の自動リトライ
- **`--broadcast`**: 複数クライアントを同時に受け付け、クライアント間でメッセージを中継(簡易チャットルーム。本家 `nc` にはない機能)
- **`--proxy`**: SOCKS5プロキシ経由で接続
- **`--tls`**: TLSで通信を暗号化(クライアント/サーバー双方対応)

## インストール

### 前提

- [Rust ツールチェイン](https://www.rust-lang.org/tools/install)(`cargo`)がインストールされていること

### ソースからビルド

```bash
git clone https://github.com/pecole/rust-netcat.git
cd rust-netcat
cargo build --release
```

ビルドが成功すると `target/release/rnc` に実行ファイルが生成されます。

### インストール(パスを通す)

```bash
cargo install --path .
```

`~/.cargo/bin/rnc` にインストールされ、`PATH` に `~/.cargo/bin` が通っていればどこからでも
`rnc` コマンドとして実行できます。

## 使い方

コマンド名は `rnc` です。

```
使用法: rnc [OPTIONS] [HOST] [PORT]

引数:
  [HOST]  接続先ホスト(クライアントモード)/ バインドアドレス(サーバーモード、デフォルト 0.0.0.0)
  [PORT]  接続先ポート(クライアントモード)/ リッスンポート(サーバーモード)

オプション:
  -l, --listen                      接続を待ち受けるサーバーモードにする
  -u, --udp                         TCP の代わりに UDP を使う
  -v, --verbose...                  詳細な出力(-v, -vv でさらに詳細)
  -k, --keep-open                   サーバーモードで、接続が終了しても待ち受けを継続する
  -p, --port <PORT>                 リッスンポートの指定(位置引数の代わり)
  -w, --timeout <TIMEOUT>           接続タイムアウト・読み取りタイムアウト(秒)
  -e, --exec <EXEC>                 接続確立後にコマンドを実行し、標準入出力を接続に流す(TCP のみ)
  -x, --hex                         通信内容を双方向ともhex形式でstderrにダンプ
      --stats                       接続終了時に転送統計(バイト数・時間・速度)を表示
      --timestamp                   --hex の出力に経過時間マーカーを付与
      --json-log <FILE>             接続/切断/データ/エラーイベントをJSON LinesでFILEに追記
      --filter <REGEX>              受信データのうちREGEXにマッチした行だけを表示
      --rate-limit <BYTES_PER_SEC>  転送速度を概ねBYTES_PER_SECに制限
      --retry <N>                   接続失敗時に最大N回リトライ(クライアントのみ)[default: 0]
      --retry-delay <SECS>          リトライ間隔(秒)[default: 1]
      --broadcast                   複数クライアントを受け付け、クライアント間でメッセージを中継
      --proxy <HOST:PORT>           SOCKS5プロキシ経由で接続(クライアントのみ)
      --tls                         TLSで通信を暗号化
      --tls-insecure                クライアント: サーバー証明書の検証をスキップ(検証用途のみ)
      --tls-ca <FILE>               クライアント: システムのトラストストアの代わりにFILEのCAのみを信頼
      --tls-cert <FILE>             サーバー: 証明書チェーンのPEMファイル
      --tls-key <FILE>              サーバー: 秘密鍵のPEMファイル
  -h, --help                        ヘルプを表示
  -V, --version                     バージョンを表示
```

### 1. TCP でメッセージを送受信する

サーバー(待ち受け側):

```bash
rnc -l -p 4444
```

クライアント(接続側、別端末で実行):

```bash
rnc 127.0.0.1 4444
```

どちらの端末でも入力した文字列がそのまま相手の画面に表示されます(標準入力 ⇔ 標準出力)。

### 2. ファイルを転送する

受信側:

```bash
rnc -l -p 4444 > received_file.txt
```

送信側:

```bash
rnc -w 2 127.0.0.1 4444 < send_file.txt
```

### 3. 複数の接続を順に受け付ける(`-k`)

```bash
rnc -l -k -p 4444
```

1 つの接続が終了しても、プロセスは終了せず次の接続を待ち受け続けます。

### 4. UDP モード

サーバー:

```bash
rnc -u -l -p 5353
```

クライアント:

```bash
rnc -u 127.0.0.1 5353
```

### 5. ポート接続確認(簡易ポートスキャン)

```bash
rnc -v -w 1 example.com 80
```

`-v` で接続結果を標準エラー出力に表示し、`-w` でタイムアウトを指定することで、
ポートが開いているかどうかを素早く確認できます。

### 6. コマンド実行と接続を結びつける(`-e`)

サーバー側で `bash` を待ち受けさせる例(いわゆるバインドシェル):

```bash
rnc -l -p 4444 -e "/bin/bash"
```

クライアント側から接続すると、リモートの `bash` に標準入出力が接続されます。

```bash
rnc 127.0.0.1 4444
```

> **セキュリティ上の注意:** このオプションは接続してきた相手に任意コマンド実行の権限を
> 与えます。インターネットに公開したホストや、許可のないネットワーク上で使用しないで
> ください。CTF・学習用のラボ環境や、許可された侵入テストなどでのみ使用してください。

### 7. 通信内容をhexダンプ・統計表示する(`-x` / `--stats`)

```bash
rnc -l -p 4444 -x --stats
```

```bash
rnc -x --stats -w 2 127.0.0.1 4444
```

送受信したバイト列がxxd風の16進ダンプとしてstderrに表示され、接続終了時に
`--- stats: sent N bytes, received N bytes, elapsed X.XXs (... KiB/s tx, ... KiB/s rx) ---`
という統計行が表示されます。`--timestamp` を併用すると、各ダンプの前に接続開始からの
経過時間(`[  0.123s]`)が付与されます。

### 8. 通信をJSON Linesでログに残す(`--json-log`)

```bash
rnc -l -p 4444 --json-log server.jsonl
```

`connect` / `disconnect` / `data` / `error` イベントが1行1JSONで追記されます。
`tail -f server.jsonl | jq` のようにリアルタイムで監視・加工できます。

### 9. 受信データを正規表現でフィルタする(`--filter`)

```bash
rnc -l -p 4444 --filter "ERROR|WARN"
```

受信した行のうち正規表現にマッチした行だけを表示します(ログの監視や、大量データの中から
特定のパターンだけを追いたい場合に便利)。バイナリデータや `-e` 実行結果には影響しません
(表示のみのフィルタで、相手に送るデータやシェルへの入力は変更されません)。

### 10. 転送速度を制限する(`--rate-limit`)

```bash
rnc -l -p 4444 --rate-limit 51200 > received_file.txt
```

指定したバイト/秒に概ね収まるよう送受信を遅延させます。低速回線のシミュレーションや、
相手サーバーへの負荷を抑えたい場合に使います。送信側・受信側どちらか片方に指定すれば
十分です(双方に指定すると、それぞれが独立に制限をかけるため、体感速度はさらに遅くなります)。

### 11. 接続失敗時にリトライする(`--retry`)

```bash
rnc --retry 5 --retry-delay 2 example.com 4444
```

接続に失敗した場合、指定回数まで・指定間隔(秒)でリトライします。相手サーバーの起動を
待ってから接続したい場合などに便利です。

### 12. 複数クライアント間のチャットルーム(`--broadcast`)

本家 `nc` にはない機能です。サーバーが複数のクライアント接続を同時に受け付け、あるクライアント
から届いたデータを他の全クライアントに配信します(サーバー自身の標準入出力は経由しません)。

```bash
rnc -l -k -p 4444 --broadcast
```

複数の端末から接続すると、簡易的なチャットルームとして使えます。

```bash
rnc 127.0.0.1 4444
```

### 13. SOCKS5プロキシ経由で接続する(`--proxy`)

```bash
rnc --proxy 127.0.0.1:1080 example.com 4444
```

指定したSOCKS5プロキシ(認証なしのみ対応)経由で接続先にCONNECTします。接続先ホスト名の
名前解決はプロキシ側で行われるため、プロキシからしか到達できないネットワークにも接続できます。

### 14. TLSで通信を暗号化する(`--tls`)

サーバー側(証明書と秘密鍵が必要):

```bash
rnc -l -p 4444 --tls --tls-cert server.pem --tls-key server-key.pem
```

クライアント側(通常はシステムのCAトラストストアで検証):

```bash
rnc --tls example.com 443
```

自己署名証明書など、システムのトラストストアにないCAで発行された証明書を使う場合は
`--tls-ca` で信頼するCA証明書を指定します。

```bash
rnc --tls --tls-ca ca.pem 127.0.0.1 4444
```

検証用に証明書チェックを完全にスキップしたい場合(**本番環境では非推奨**):

```bash
rnc --tls --tls-insecure 127.0.0.1 4444
```

## 開発

```bash
cargo build           # デバッグビルド
cargo build --release # リリースビルド
cargo test             # テスト実行(ユニットテスト+実際にソケット通信する統合テスト)
cargo clippy            # Lint
```

統合テストの一部(TLS関連)は `openssl` コマンドが利用可能な場合のみ実行され、
なければ自動的にスキップされます。
